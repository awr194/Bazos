# Bazos.cz — аналитика спроса и предложения

Инструмент собирает объявления со всех 20 рубрик [Bazos.cz](https://www.bazos.cz) и их
подкатегорий, отслеживает динамику просмотров и скорость снятия объявлений, отдельно собирает
объявления покупателей («куплю») и показывает спрос и предложение в интерактивном дашборде Streamlit.

## Рубрики и подкатегории

Рубрики (поддомены `https://<код>.bazos.cz/`), список — в `src/config.py`:

| Код | Рубрика | Код | Рубрика |
|---|---|---|---|
| `zvirata` | Животные | `foto` | Фото |
| `deti` | Детские товары | `elektro` | Электроника |
| `reality` | Недвижимость | `sport` | Спорт |
| `prace` | Работа | `hudba` | Музыка |
| `auto` | Автомобили | `vstupenky` | Билеты |
| `motorky` | Мотоциклы | `knihy` | Книги |
| `stroje` | Техника и станки | `nabytek` | Мебель |
| `dum` | Дом и сад | `obleceni` | Одежда |
| `pc` | Компьютеры | `sluzby` | Услуги |
| `mobil` | Мобильные телефоны | `ostatni` | Прочее |

Подкатегории (`https://mobil.bazos.cz/apple/`, `https://auto.bazos.cz/skoda/` …) не зашиты в код,
а читаются с сайта:

```bash
python -m src.scraper --discover                          # справочник рубрик и подкатегорий → таблица taxonomy
python -m src.scraper --by-subcategory --no-details        # обойти все подкатегории, объявления получат тег
python -m src.scraper --categories mobil --subcategory apple --pages 3   # одна подкатегория
```

`--discover` также сообщает, если на главной www.bazos.cz появилась рубрика, которой нет в
`config.py`; любую такую рубрику можно сразу собирать: `--categories <код>`.

## Метрики

| Метрика | Определение |
|---|---|
| **VPH** (Views Per Hour) | `(views_now − views_initial) / hours_passed` — между первым и последним снимком просмотров |
| **Время жизни** | `removed_at − first_seen` для снятых объявлений (часы) |
| **Ликвидность** | доля объявлений, ставших неактивными быстрее 24 / 48 часов |
| **Demand score** | `VPH × (1 + log10(1 + просмотры))` — сортировка таблицы активных объявлений |
| **Ценовая эластичность** | доля продаж < 48 ч по ценовым квартилям внутри категории и наклон этой зависимости |
| **Явный спрос** | объявления покупателей «Koupím / Sháním / Hledám» (`listing_type = demand`) |
| **Ищут / продают** | число объявлений «куплю» к числу «продаю» по ключевому слову; > 1 — дефицит |
| **Бюджет / цена** | медианный бюджет покупателей к медианной цене продавцов в категории |

## Структура проекта

```
├── dashboard.py          # Streamlit-дашборд
├── src/
│   ├── config.py         # URL категорий, User-Agent'ы, задержки, пороги
│   ├── db.py             # SQLite: схема, контекстный менеджер соединений, upsert/снимки
│   ├── scraper.py        # сбор (httpx + selectolax), режим --update, --seed-sample
│   └── analytics.py      # VPH, оборачиваемость, ключевые слова, цена/эластичность
├── tests/                # pytest: парсинг на HTML-фикстурах, БД, аналитика
├── data/                 # здесь создаётся bazos.db
├── requirements.txt
└── requirements-dev.txt  # + ruff, pytest
```

База — SQLite с двумя таблицами:

* `listings` — одно объявление: ID, категория, запрос, заголовок, цена (int, CZK), город, PSČ,
  URL, дата публикации, `first_seen` / `last_seen` / `removed_at`, `is_active`,
  `views_initial` / `views_current`;
* `listing_snapshots` — временной ряд: `captured_at`, `views`, `price_czk`, `is_active`;
* `taxonomy` — справочник рубрик и подкатегорий (`--discover`);
* `market_counts` — замеры общего объёма рынка: сколько всего объявлений в рубрике и сколько
  находит поиск по словам спроса («Zobrazeno 1–20 inzerátů z N»).

Поле `listings.listing_type`: `offer` — продаю, `demand` — ищу/куплю, `buyout` — перекупщики
(«Vykoupím vaše auto», «Výkup mobilů»); их держим отдельно, чтобы не завышать спрос. Старые базы
получают колонку автоматически при `init_db`.

## Установка

Нужен Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # для разработки: pip install -r requirements-dev.txt
python -m src.scraper --init-db    # создать data/bazos.db
```

Путь к базе можно переопределить переменной окружения `BAZOS_DB_PATH` или флагом `--db`.

## Быстрый старт с демо-данными

```bash
python -m src.scraper --seed-sample   # 50 объявлений (41 «продаю» + 9 «куплю») со снимками за 5 дней
streamlit run dashboard.py            # http://localhost:8501
```

Демо-записи получают ID от `900000001`, поэтому не пересекаются с реальными; повторный запуск
перезаписывает только их.

## Сбор реальных данных

```bash
# первые 2 страницы (по 20 объявлений) всех 20 рубрик + страницы объявлений для «Vidělo»
# (~840 запросов ≈ 35–40 минут; для быстрого обзора добавьте --no-details: 40 запросов ≈ 2 минуты)
python -m src.scraper

# только телефоны и ПК, 3 страницы, не более 20 карточек на категорию
python -m src.scraper --categories mobil pc --pages 3 --detail-limit 20

# поиск по запросу — запрос сохраняется и участвует в рейтинге ключевых слов
python -m src.scraper --categories mobil --query "iphone 13"

# быстрый сбор без открытия карточек (просмотры берутся из списка, если они там есть)
python -m src.scraper --no-details
```

### Режим обновления

```bash
python -m src.scraper --update            # перепроверить все активные объявления
python -m src.scraper --update --limit 100 --categories auto
```

Для каждого активного объявления запрашивается его страница:

* 404/410, текст «Inzerát byl vymazán» или редирект с карточки — `is_active = 0`, фиксируется `removed_at`;
* иначе — новый снимок просмотров (`Vidělo: X lidí`) и цены.

VPH и время до продажи появляются только при повторных проверках, поэтому `--update` стоит
запускать по расписанию, например каждые 2–3 часа через cron:

```cron
0 */3 * * * cd /path/to/Bazos && .venv/bin/python -m src.scraper --update >> data/update.log 2>&1
30 */6 * * * cd /path/to/Bazos && .venv/bin/python -m src.scraper --pages 2 >> data/scrape.log 2>&1
```

### Бережное отношение к сайту

* Случайная пауза 1,5–3,5 с перед каждым запросом (`MIN_DELAY` / `MAX_DELAY` в `src/config.py`).
* Ротация реалистичных User-Agent'ов, заголовки `Accept-Language: cs-CZ`.
* При `429` / `5xx` — повтор с учётом `Retry-After` или экспоненциальной паузой (до 3 попыток).
* Соблюдайте условия использования Bazos.cz и не уменьшайте задержки.

### Устойчивость парсинга

Парсер не завязан на конкретные CSS-классы: карточка объявления находится как самый широкий
контейнер вокруг ссылки `/inzerat/<id>/`, в котором нет ссылок на другие объявления. Цена, PSČ,
дата `[26.9. 2026]` и просмотры извлекаются регулярными выражениями; классы с фрагментами
`cena`, `lok`, `view`, `popis` используются лишь как подсказка (текст описания исключается при
поиске цены, чтобы не поймать «původně 20 000 Kč»).

## Спрос: что ищут люди

Bazos не публикует статистику поисковых запросов, поэтому спрос измеряется двумя способами:

1. **Явный спрос** — объявления покупателей. Люди сами пишут «Koupím iPhone 13 do 8 000 Kč»,
   «Sháním Škoda Fabia». Скрейпер ищет их запросами `koupím`, `sháním`, `hledám`
   (`DEMAND_QUERIES` в `src/config.py`), классифицирует по началу заголовка/описания и
   извлекает бюджет из заголовка.
2. **Скрытый спрос** — просмотры и VPH объявлений о продаже (вкладка «Предложение»).

```bash
python -m src.scraper --demand --pages 3     # объявления «куплю» во всех рубриках
python -m src.scraper --count                # общий объём рынка: 4 запроса на рубрику
```

После обновления правил классификации пересчитайте уже собранную базу:
`python -m src.scraper --reclassify`. Демо-данные удаляются командой
`python -m src.scraper --clear-sample` (в дашборде они скрыты, если есть реальные данные).

Важно: соотношение «собрано куплю / собрано продаю» — не рыночное. Спрос собирается прицельным
поиском по всем рубрикам, а продажи — только с первых страниц, поэтому для оценки рынка
используйте замер `--count` (карточка «Спрос на 1000 объявлений рынка»).

`--count` ничего не сохраняет, кроме итоговых чисел: сколько объявлений в рубрике и сколько
результатов по каждому слову спроса. Запускайте его раз в день, чтобы видеть динамику.

## Сколько данных можно собрать

Узкое место — пауза между запросами (в среднем 2,5 с), а не база. Это ≈ 1 200–1 400 запросов в час:

| Режим | Запросов на объявление | Объявлений в час | В сутки |
|---|---|---|---|
| `--no-details` (только списки, по 20 на страницу) | 0,05 | ~25 000 | ~600 000 |
| обычный сбор (список + карточка ради «Vidělo») | ~1,05 | ~1 300 | ~30 000 |
| `--update` (перепроверка активных) | 1 | ~1 300 | ~30 000 |
| `--count` | 4 запроса на рубрику | — | — |

Практический предел отслеживания — цикл `--update`: чтобы VPH и время продажи были точными,
каждое объявление нужно перепроверять раз в 2–3 часа, то есть одновременно можно вести
**≈ 3 000–4 000 активных объявлений** с одного IP. Всё, что сверх, — в режиме `--no-details`
(дёшево, но без проверки снятия) либо реже. SQLite спокойно держит сотни тысяч объявлений и
миллионы снимков.

Повторный обход списков (`--no-details`) тоже добавляет снимки просмотров для уже известных
объявлений, если Bazos показывает счётчик в списке, — это самый дешёвый способ считать VPH.

## Дашборд

```bash
streamlit run dashboard.py
```

* **Боковая панель:** фильтр рубрик (пусто — все 20) и подкатегорий, переключатель группировки
  таблиц «по рубрикам / по подкатегориям», период (по дате первого появления), кнопки
  «Перечитать базу», «Загрузить демо-данные», а также сбор, проверка активных, сбор спроса,
  обновление справочника рубрик и обход подкатегорий прямо из интерфейса.
* **Карточки:** активные объявления, медианный VPH, самая быстрая категория и её среднее время жизни.
* **График 1:** топ-15 объявлений по VPH (горизонтальные столбцы, цвет — категория).
* **График 2:** гистограмма времени до продажи с отметками 24 и 48 ч.
* **Вкладки:** топ-10 ключевых слов/запросов по среднему VPH, оборачиваемость категорий
  (быстрая — среднее время жизни < 48 ч), медианная цена быстро проданных и ценовая эластичность.
* **Таблица:** поиск по названию/городу/PSČ, сортировка по demand score, ссылки на объявления.
* **Вкладка «Спрос: что ищут люди»:** число объявлений «продаю» и «куплю», объём рынка по замерам
  `--count`, график «ищут против продают» по ключевым словам, сравнение бюджета покупателей с ценой
  продавцов по категориям, таблица объявлений покупателей с поиском.

Вкладка «Предложение» считает метрики только по объявлениям `offer`.

pip install -r requirements-dev.txt
